1. R version

1.1 R version provided by authors

Follow the steps for your operating system below.

  • Windows
  • macOS
  • Linux
  1. Download and install the required R version from the CRAN archive.
  2. Download and install the associated Rtools version from CRAN. RStudio will automatically select the correct Rtools for the R version you are running. If you already have the correct version installed, skip this step.
  3. In RStudio, navigate to Tools → Global Options. Under R version, click Change.
  4. Select the required R version as specified by the authors, and click OK.
  5. Click Apply.
  6. A pop-up will appear noting that RStudio must be restarted for the change to take effect.
  7. Close and reopen RStudio.
  8. Verify the correct R version is active by running sessionInfo() in the Console.

We recommend using rig (the R Installation Manager) to install and switch between multiple R versions.

Install rig (if not already installed) by opening Terminal and running:

brew install --cask rig

If you do not have Homebrew, install it from brew.sh first, or download rig directly from its GitHub releases.

Install the required R version by running the following in Terminal, replacing x.x.x with the required version number:

rig install x.x.x

Switch the R version in RStudio:

  1. In RStudio, navigate to Tools → Global Options. Under R version, click Change.
  2. Select the required R version and click OK.
  3. Click Apply.
  4. Close and reopen RStudio.
  5. Verify the correct R version is active by running sessionInfo() in the Console.

Note — Apple Silicon vs Intel: Make sure you have the correct build of R for your chip. Check your chip type under Apple menu → About This Mac. rig installs the correct build automatically.

Note — compilation errors: If package installation fails with compilation errors, install the Xcode Command Line Tools by running xcode-select --install in Terminal.

2. Packages

2.1 No information on packages

If no package version information is available, use the newest available package versions. Every time you start a new reproduction, make sure all installed packages are up to date before running any code.

  1. In RStudio, navigate to Tools → Check for Package Updates… → Select All → Install Updates.
  2. Click Yes when prompted to restart RStudio before installation.

2.2 Function calls in script only

If the script contains library() or require() calls but the packages are not yet installed on your system, add an install.packages() call to the script. This constitutes a manual change.

Adjust the package names below to match those needed by the script:

########################
#### MANUAL CHANGES ####

install.packages(c("package1", "package2", "package3"))

########################

2.3 List of packages without versions

If a list of required packages is provided (e.g., in a README or documentation file) but no version numbers are given, install all listed packages at their current versions. This constitutes a manual change.

Add the following code to the script, replacing the package names with those listed by the authors:

########################
#### MANUAL CHANGES ####

install.packages(c("package1", "package2", "package3"))

########################

After installation, ensure that library() calls for all packages are present in the script (see Section 2.2).

2.4 Packages with versions

If specific package versions are provided (e.g., from a sessionInfo() output or a list in the documentation), install the exact versions using the remotes package. This constitutes a manual change.

########################
#### MANUAL CHANGES ####

# Install remotes if not already available
if (!requireNamespace("remotes", quietly = TRUE)) install.packages("remotes")

# Install specific package versions as listed by the authors
remotes::install_version("package1", version = "1.2.3")
remotes::install_version("package2", version = "4.5.6")
remotes::install_version("package3", version = "0.9.1")

########################

Note: remotes::install_version() downloads the package source from CRAN and compiles it locally. This may take longer than a regular installation and may require build tools (Rtools on Windows, Xcode Command Line Tools on macOS, or build-essential on Linux — see Section 1).

2.5 Renv

An R project that uses renv will automatically initialize the renv library when you open the .Rproj file — you will see a confirmation message in the Console. The working directory is also set automatically to the project folder.

A correctly set-up renv project will include code to restore the package library from the lockfile:

renv::restore()  # restores packages from the renv.lock file

library(package1)  # library() calls for all needed packages
library(package2)

If the project does not include renv::restore(), add this line yourself before the library() calls. This constitutes a manual change — record it in the protocol and refer to Section 3.4.

3. Manual Changes

A manual change is any action that requires you as the reproducer to (1) write code not written by the original authors, and/or (2) modify any code provided by the original authors.

This applies even when the required changes are described in the authors’ own instructions: if you have to write or alter code, it is a manual change. Record every manual change in the protocol, including what was changed and why.

3.1 Set the working directory

Setting the working directory manually is only necessary if the materials are not part of an R project. R projects (recognizable by a .Rproj file in the top-level folder) set the working directory automatically when opened in RStudio — no manual step is needed.

If the materials are not an R project, check first whether the script sets the working directory itself. For example, the following code sets the working directory to the folder containing the currently open script:

setwd(dirname(rstudioapi::getActiveDocumentContext()$path))

There may be other approaches authors use to set the working directory programmatically — check the script carefully before assuming this has not been handled.

If no automatic method is in place, you must set the working directory manually to the top-level folder of the shared materials — even if the script does not explicitly instruct you to do so. Many scripts save output to the working directory, so setting it correctly ensures output files end up where you expect them.

In RStudio, navigate to Session → Set Working Directory → Choose Directory… and select the top-level folder of the shared materials.

Alternatively, add the following code to the script (manual change):

  • Windows
  • macOS
  • Linux
########################
#### MANUAL CHANGES ####

setwd("C:/path/to/shared/materials")

########################
########################
#### MANUAL CHANGES ####

setwd("/Users/yourname/path/to/shared/materials")

########################
########################
#### MANUAL CHANGES ####

setwd("/home/yourname/path/to/shared/materials")

########################

3.2 Change filepaths

Authors often use absolute filepaths that are specific to their own computer (e.g., C:/Users/author/Documents/project/data.csv or /home/author/project/data.csv). These paths will not exist on your system and must be updated.

To identify and fix hardcoded paths:

  1. Search the script for filepath strings. These are typically character strings containing slashes and folder or file names (e.g., "C:/Users/..." or "/home/...").
  2. Replace each absolute path with the correct path on your system. Where possible, use a relative path from the working directory instead of an absolute path (e.g., "data/data.csv" instead of a full system path). Relative paths make the script more portable.
  3. Record each change in the protocol as a manual change.

Example:

########################
#### MANUAL CHANGES ####

# Original author's path (does not exist on your system):
# data <- read.csv("C:/Users/author/Documents/project/data.csv")

# Replaced with a relative path from the working directory:
data <- read.csv("data/data.csv")

########################

Note — Windows paths: On Windows, R accepts both forward slashes (/) and escaped backslashes (\\). Either "C:/path/to/file.csv" or "C:\\path\\to\\file.csv" is valid in R.

3.3 Comment out erroneous or irrelevant code

Occasionally, a script contains code that produces errors or performs actions that are irrelevant to the reproduction.

In these cases, comment out the relevant line(s) and add a brief explanation so the change is transparent. This constitutes a manual change.

An RStudio shortcut to easily comment out chunks of code is by selecting the code you want to comment out and hitting Ctrl + Shift + C.

########################
#### MANUAL CHANGES ####

# Commented out: sends results via email — not needed for reproduction
# send_results(to = "author@university.edu", file = "results.pdf")

# Commented out: references a file not included in shared materials
# supplementary <- read.csv("C:/Users/author/extra_data/supplement.csv")

########################

Important: Only comment out code that is genuinely irrelevant to or obstructive of the reproduction. Do not comment out code that contributes to producing the research outputs. If you are unsure, consult the protocol or raise the issue with your team.

3.4 Changes related to dependencies

Any of the following actions constitutes a manual change and must be recorded in the protocol:

  • Adding renv::restore(): If an renv project does not include this call, you add it yourself to restore the package library from the lockfile (see Section 2.5).

  • Adding install.packages(): If package installation is not included in the script, you add it to install missing packages (see Sections 2.2 and 2.3).

  • Adding library() calls: If required packages are described in a README or documentation but the library() calls are absent from the script, you add them yourself.

  • Installing specific package versions: If you use remotes::install_version() to install packages at the versions specified by the authors (see Section 2.4), this code must be added manually to the script.

In all cases, clearly mark any added code with the MANUAL CHANGES comment block used throughout this appendix and indicate the manual changes in the protocol.
